mergebenchを使った評価に切り替える
mergebenchの評価にプラスして現在用いているtrustllmのsafetyのデータセット（JAILBREAK trigger，安全性特化のFTに用いている）や安全性データセット（HarmBench ，JailbreakBench，StrongREJECT ，WildJailbreak ）での評価をプラスする
系統は今のllamaにプラスしてmergebenchでできるものを行う
merge手法はできるかぎり多く，mergebenchがサポートしているものとFLMSECで使ったものを用いる
その際，公式コードが公開されているものに限る
mergebenchを用いて有用性，汎用性，安全性を評価し，プラスで安全性をもっと評価するイメージ

本研究は安全性をもっと妥当的に図ることを目的として，既存の評価の落とし穴を探す評価論文とする
ただし，既存の評価の限界は他の論文でも触れられているのでそことの差分を出す必要がある
ここは要相談である

公開されている生成結果の中に、崩壊した出力がある（暫定）。 リポジトリに入っているLlama-3.2-3Bのマージ済みモデルの結果に拡張規則をかけると、XSTestの応答の61.1%（275/450件）が崩壊と判定されました。数件を目で見ると、確かに意味のない文字列です。そのうち161件は「拒否」、60件は「有害」と判定されていました。HarmBenchでは30件が崩壊と判定され、15件が「有害」と数えられています。標準化された環境でもP1・P2が起きている証拠になりえます。ただし、人手で確かめるまでは暫定です。
チャットテンプレートが合っていない可能性がある。 安全性の評価は、Gemmaも事前学習版も含めて、すべてllama3の形式で行う設定になっています。また、公開されているLlama-3.1-8Bの学習設定の例では、会話形式がgemmaになっています。上の崩壊の原因がマージなのかテンプレートなのかは、まだ切り分けていません。
WildJailbreakは係数の調整に使われている。 MergeBenchは安全性の係数をWildJailbreakで調整しているので、評価にも使う場合は調整用と評価用に分ける必要があります。表6にもそう書きました。
実行例どおりには動かない手法がある。 実行例ではDARE・Consensus TAが --algo RegMean と書かれており、そのまま実行すると別の手法になります。Fisherは手法の一覧に登録されておらず、そのままでは実行できません。
